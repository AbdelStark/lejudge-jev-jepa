# AGENTS.md — how to build LeJudge

You are a coding agent building `lejudge`, a natural-language cost module for JEPA world-model planning. This file is your operating manual. Read it fully before your first change. Read `RFC-0008` next, then the RFC you are implementing.

## What this repo is

LeWorldModel (LeWM) imagines latent futures. Linear probes turn each imagined latent into a few words. Jev (TypeSafe's System One model) answers typed yes/no questions about those words. Code folds the probabilities into the CEM cost. No LLM in the planning loop, no generated text anywhere in the method.

Read in this order: `README.md` → `RFC-0008` → `SPEC.md` → the RFC for your task → the relevant skill in `skills/`.

## Ground rules

1. **Jev reads words, never numbers.** Anything numeric is bucketed in `vocab/` before it reaches a state. If you find a float in a `StepFacts`, that is a bug.
2. **Constraint text and facts never share a field.** `constraints` and `candidates` are separate top-level keys. Facts are code-generated from a closed vocabulary.
3. **Arithmetic lives in code.** Aggregation (`max`, `min`, expectation, first-index), thresholds, hysteresis and λ are Python. Never ask Jev to count, compare numbers or dates, or reason through indirection. See `skills/lejudge-jev-questions`.
4. **Every external call is cached and traced.** Use `judge/cache.py`; never call the TypeSafe or LLM APIs directly. Tests and `make paper` run with `LEJUDGE_MODE=offline`.
5. **Baselines share the interface.** `OracleJudge`, `KeywordJudge`, `LLMJudge` implement the same `judge()` as `JevJudge` and receive identical inputs.
6. **No time estimates.** Do not write durations, deadlines or "weeks" anywhere. Plans are ordered lists of milestones with acceptance tests.
7. **No fabricated numbers.** Placeholders in the paper draft are `[X]`. Any number in `docs/` or `paper/` must trace to a row in `artifacts/results/`.
8. **Pin everything.** Model ids, checkpoint revisions, library versions, vocab and bank versions appear in every result row.
9. **Small PRs, one RFC at a time.** Each PR names its RFC and ticks acceptance tests in the description.
10. **Write the decision log.** Any choice not fixed by an RFC goes into `docs/DECISIONS.md` with the date, the options and the reason.

## Environment setup

```
uv venv --python=3.10 && source .venv/bin/activate
uv pip install 'stable-worldmodel[all]'
uv pip install "typesafe-sdk>=0.5.7" --extra-index-url https://pypi.typesafe.ai/
uv pip install -e .
export STABLEWM_HOME=~/.stable-wm
hf download quentinll/lewm-pusht --local-dir $STABLEWM_HOME/hf_pusht   # then run scripts/convert_checkpoint.py (from le-wm README)
export TYPESAFE_API_KEY=...   # only for LEJUDGE_MODE=live
```

Verify the exact `stable_worldmodel` API (`AutoCostModel`, `CEMSolver`, `WorldModelPolicy`, `PlanConfig`, `World`) against the installed version before writing the adapter; it is under active development and may differ from the README snapshot in `skills/lejudge-swm-planning/references/`.

## Working style

- Before editing, run `pytest -q` and `lejudge lint` and paste results in the PR.
- Prefer pure functions and dataclasses; typed everywhere; `ruff` clean.
- When an RFC is ambiguous, implement the simplest reading, add a DECISIONS entry, and flag it in the PR.
- When you need Jev, write the question first in `skills/lejudge-jev-questions/references/bank.md` style and run the lint; then implement.
- Never delete traces or cache entries; add new run ids.

## Definition of done for the MVP

See `SPEC.md` § 9. The MVP is done when every box is ticked and `make paper` runs offline on a clean clone.

## Things that will tempt you and are wrong

- Sending coordinates or angles as numbers "just for this one question".
- Letting the LLM baseline see a different prompt "because it needs more context".
- Tuning paraphrases or thresholds after looking at held-out results.
- Writing "this takes about a week" anywhere.
- Calling the API from a test.
